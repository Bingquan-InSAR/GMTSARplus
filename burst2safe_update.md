# GMTSAR Compatibility with Burst-Level Sentinel-1 Products

## 1. Purpose

This document describes a GMTSAR-side compatibility issue encountered when processing burst-level Sentinel-1 SAFE products generated by `burst2safe`.

The `burst2safe` products provide valid Sentinel-1 SAFE metadata and measurements. The problem occurs when conventional GMTSAR frame-assembly scripts process the burst-level SAFE structure. GMTSAR+ adapts this workflow for burst products.

## 2. Comparison Using the Same Input

The following scripts were tested with the same SAFE file list, orbit file, geographic control points, polarization, and processing environment.

| Script | Source | Input | Result |
|---|---|---|---|
| `create_frame_tops.csh` | Official GMTSAR | Identical burst SAFE list | Segmentation fault |
| `GMTSAR_s1_createTOPSframes.csh` | pSAR workflow | Identical burst SAFE list | Segmentation fault |
| `GMTSAR_s1_createTOPSframes_burst.csh` | Modified in GMTSAR+ | Identical burst SAFE list | Completed successfully and generated the frame-level SAFE |

The first two scripts are conventional frame-assembly workflows. The third script was modified for the structure and metadata characteristics of burst-level products.

## 3. GMTSAR+ Modification

The affected XML field is:

```text
imageAnnotation/imageInformation/sliceList
```

The tested annotation XML contained the following empty node:

```xml
<sliceList count="0">
</sliceList>
```

This is syntactically valid XML. However, the GMTSAR `make_s1a_tops` stage in the tested environment did not robustly process this representation and terminated with a segmentation fault. GMTSAR+ normalizes the empty node to:

```xml
<sliceList count="0"></sliceList>
```

The modification is applied in `GMTSAR_s1_createTOPSframes_burst.csh` after frame assembly. It does not change timing, orbit, geolocation, calibration, phase, amplitude, or measurement values.

The relevant GMTSAR components are:

```text
GMTSAR_s1_createTOPSframes_burst.csh  burst-oriented frame assembly
make_s1a_tops                         Sentinel-1 XML/TIFF processing
assemble_tops                         burst/frame assembly
gmtsar_preproc_batch_tops_esd.csh     downstream SLC and ESD processing
```

The pSAR script `pSAR_gmtsar_s1.py` orchestrates the workflow and calls the burst-oriented script; it does not independently generate the Sentinel-1 annotation metadata.

## 4. Minimal Reproducible Example

The following command was used for the Cebu test case. Replace the paths with the corresponding local paths when reproducing the test.

```bash
GMTSAR_s1_createTOPSframes_burst.csh \
    SAFE_filelist_20250918 \
    /path/to/S1A_OPER_AUX_POEORB_OPOD_20251008T070612_V20250917T225942_20250919T005942.EOF \
    20250918_twopins.ll \
    1 \
    /path/to/cebu/raw
```

Here, `1` denotes VV polarization. The same input data were also processed with the official GMTSAR script and the pSAR script.

For the isolated parser test, the same XML/TIFF pair was passed to `make_s1a_tops` before and after normalization:

```bash
make_s1a_tops input.xml input.tiff test_before 0 > before.log 2>&1
echo $?

# Apply the empty sliceList normalization.

make_s1a_tops input.xml input.tiff test_after 0 > after.log 2>&1
echo $?
```

Observed results:

| Condition | Result |
|---|---|
| Without XML normalization | `Segmentation fault`, exit status `139` |
| With XML normalization | Processing completed successfully |

## 5. Upstream Verification

The upstream `burst2safe` repository was checked at:

```text
Repository: https://github.com/ASFHyP3/burst2safe
Release: v2.0.3
Commit: b5436cea79885bf95bc49114060b906392741917
```

The checked upstream code creates an empty `sliceList` by setting its count to zero and removing its child elements. No GMTSAR-specific compatibility normalization was found at this commit. Therefore, the normalization described here is a downstream compatibility adjustment in GMTSAR+ rather than a correction to the burst2safe scientific processing algorithm.

Large Sentinel-1 SAFE, TIFF, and ZIP files are not included. The test can be reproduced with the same local burst products and the command provided above.
