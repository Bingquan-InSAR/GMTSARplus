# Supplementary Material: burst2safe--GMTSAR Compatibility Test

## 1. Purpose

This document records the compatibility test between burst-level Sentinel-1 SAFE products generated by `burst2safe` and the GMTSAR processing workflow.

The test used the same burst SAFE list, orbit file, geographic control points, polarization, and processing environment for all three scripts.

## 2. Script Comparison

| Script | Source | Input | Result |
|---|---|---|---|
| `create_frame_tops.csh` | Official GMTSAR | Identical burst SAFE list | Segmentation fault |
| `GMTSAR_s1_createTOPSframes.csh` | pSAR workflow | Identical burst SAFE list | Segmentation fault |
| `GMTSAR_s1_createTOPSframes_burst.csh` | Modified in GMTSAR+ | Identical burst SAFE list | Completed successfully and generated the frame-level SAFE |

The first two scripts are conventional frame-assembly workflows. The third script was adapted for burst-level SAFE products.

## 3. GMTSAR+ Modification

The affected XML field is:

```text
imageAnnotation/imageInformation/sliceList
```

The burst annotation XML contained the following empty node:

```xml
<sliceList count="0">
</sliceList>
```

This is syntactically valid XML, but the tested GMTSAR `make_s1a_tops` processing stage did not robustly handle this representation. GMTSAR+ normalizes it to:

```xml
<sliceList count="0"></sliceList>
```

This normalization does not modify timing, orbit, geolocation, calibration, phase, amplitude, or measurement values.

The `grep` operation in the script is diagnostic only. The XML change is performed by the following normalization step:

```csh
foreach f ($outdir/$newname/annotation/*.xml)
    perl -0777 -pi.bak -e \
    's#<sliceList count="0">\s*</sliceList>#<sliceList count="0"></sliceList>#g' \
    "$f"
    rm -f "$f.bak"
end
```

## 4. Minimal Reproducible Example

The following command was used for the Cebu test case:

```bash
GMTSAR_s1_createTOPSframes_burst.csh \
    SAFE_filelist_20250918 \
    /home/insar/Programs/Copphil-local/S1_ORB/aux_poeorb/S1A_OPER_AUX_POEORB_OPOD_20251008T070612_V20250917T225942_20250919T005942.EOF \
    20250918_twopins.ll \
    1 \
    /InSAR_worker/PROCESSED/GLOF/cebu/raw
```


Observed results:

| Condition | Result |
|---|---|
| Without XML normalization | `Segmentation fault` |
| With XML normalization | Processing completed successfully |

## 5. Processing Modules

The relevant processing modules are:

```text
GMTSAR_s1_createTOPSframes_burst.csh  burst-oriented frame assembly
make_s1a_tops                         Sentinel-1 XML/TIFF processing
assemble_tops                         burst/frame assembly
gmtsar_preproc_batch_tops_esd.csh     downstream SLC and ESD processing
```

`pSAR_gmtsar_s1.py` orchestrates the workflow and calls `GMTSAR_s1_createTOPSframes_burst.csh`; it does not independently generate the Sentinel-1 annotation metadata.
