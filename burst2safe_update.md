# GMTSAR Compatibility with Burst-Level Sentinel-1 Products

## 1. Scope

This document records a GMTSAR-side compatibility limitation encountered
when processing burst-level Sentinel-1 SAFE products.

The burst SAFE products and source annotation XML files were generated by
`burst2safe` and contain a complete empty `sliceList` element. The observed
failure occurs after the conventional GMTSAR frame-assembly workflow rewrites
this element as an unclosed opening tag.

A second compatibility issue concerns the `numberOfSamples` metadata field
after multiple bursts are assembled into a frame.

## 2. Controlled Script Comparison

The following scripts were tested with the same SAFE file list, orbit file,
geographic control points, polarization, and processing environment.

| Script | Source | Input | Result |
| --- | --- | --- | --- |
| `create_frame_tops.csh` | Official GMTSAR | Identical burst SAFE list | Segmentation fault |
| `GMTSAR_s1_createTOPSframes.csh` | pSAR workflow | Identical burst SAFE list | Segmentation fault |
| `GMTSAR_s1_createTOPSframes_burst.csh` | Modified in GMTSAR+ | Identical burst SAFE list | Completed successfully and generated the frame-level SAFE |

The first two scripts are conventional frame-assembly workflows. The third
script was adapted for the structure and metadata characteristics of
burst-level products.
